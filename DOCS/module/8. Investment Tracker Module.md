# 8. Investment Tracker Module

**Module Type:** Wealth Tracking  
**Build Phase:** Phase 2  
**Dependencies:** Module 1 (Account & Wallet), Module 2 (Transaction Engine)

---

## Purpose

Portfolio-level tracking of all investment instruments with performance analytics. Supports mutual funds, stocks, FDs, PPF, NPS, gold, and crypto — all with manual entry (no API-based auto-sync). Users track what they own, at what price, and see how their portfolio is performing over time. SIP tracking for recurring investments is also included.

## Functional Requirements

### Investment Holding Management

**FR-8.1:** User can add an investment holding with:
- Type (required, enum: mutual_fund / stock / fd / ppf / nps / gold / crypto / other)
- Name (required, e.g., "Axis Bluechip Fund", "SBI FD #1234")
- Units (required for unit-based instruments, positive decimal)
- Buy Price (required for unit-based, per-unit average cost)
- Current Price (required for unit-based, current NAV or market price)
- Current Value (auto-computed: units × current_price for unit-based; user-entered for non-unit instruments)
- Invested Value (auto-computed: units × buy_price for unit-based; user-entered for non-unit)
- Purchase Date (required, first purchase date)
- Maturity Date (for FDs, bonds, and other fixed-term instruments)
- Account ID (optional, FK → accounts(id), links to account showing cash balance used)
- Category (optional, for classification: equity / debt / hybrid / gold / cash_equiv / crypto / other)
- Notes (optional)
- Is Active flag (1 = active holding, 0 = closed/sold)

**FR-8.2:** User can edit holdings. Changes to units, buy price, or current price recalculate invested value, current value, and returns.

**FR-8.3:** User can mark a holding as "Closed" when fully sold or matured. Closed holdings retain full history.

### Portfolio Dashboard

**FR-8.4:** The portfolio dashboard shows:
- Total invested value (sum of invested_value across all active holdings)
- Total current value (sum of current_value across all active holdings)
- Absolute return (current value - invested value)
- Percentage return ((current value - invested value) / invested value × 100)
- Number of active holdings
- Number of holdings in profit vs in loss
- A summary card per holding: name, type, units, invested, current, returns %, color indicator (green = profit, red = loss)

**FR-8.5:** Holdings on the dashboard are sorted by:
- Default: returns percentage ascending (worst performers first — to surface problem areas)
- User can toggle sorting by: name, invested value, current value, returns %, type

### Asset Allocation

**FR-8.6:** A donut/bar chart shows portfolio breakdown by asset class category:
- Equity (mutual funds - equity, stocks)
- Debt (FDs, PPF, debt mutual funds, bonds)
- Hybrid (hybrid mutual funds)
- Gold (gold ETFs, physical gold, sovereign gold bonds)
- Cash Equivalents (savings account balances from Module 1 — if linked)
- Crypto
- Other

**FR-8.7:** Each slice shows category name, total value, and percentage of portfolio. User can click a slice to see which holdings comprise that category. Clicking a slice pre-applies the category filter to the holdings list (FR-8.19).

### Search & Filter

**FR-8.17:** The holdings list has a search box. It performs a case-insensitive substring match on the holding `name` (and `notes`), applied client-side over the already-loaded list with a 200ms debounce. A live result count is shown. Backed by the GIN trigram index (`idx_inv_name_trgm`) when server-side filtering is enabled at scale.

**FR-8.18:** User can filter holdings by instrument type (multi-select): mutual_fund / stock / fd / ppf / nps / gold / crypto / other.

**FR-8.19:** User can filter holdings by asset class category (multi-select): equity / debt / hybrid / gold / cash_equiv / crypto / other. The FR-8.7 asset allocation donut click pre-applies this filter.

**FR-8.20:** User can filter holdings by status: Active / Closed. Closed holdings retain full history and are visually tagged, not hidden.

**FR-8.21:** All filters combine with AND logic. Active filters are shown as removable chips above the list with a "Clear all" action (mirroring FR-2.18). An empty state is shown when no holdings match. Portfolio summary cards (FR-8.4) always reflect the full portfolio — filters only narrow the holdings list, never the summary totals.

### XIRR Returns

**FR-8.22:** The holding detail view computes XIRR (Extended Internal Rate of Return) from `investment_transactions` (buy/sell/reinvestment rows as cash flows) plus the holding's current value as the final cash flow. Inputs: each transaction's date + signed amount (buys negative, sells positive), and the current market value on today's date. Output: annualized return % (e.g., 14.2%).

**FR-8.23:** XIRR is computed client-side (standard Newton-Raphson iteration on the NPV function) over the loaded purchase history — no server call, no schema change. The portfolio dashboard shows an aggregate XIRR computed on the combined cash flows of all active holdings, next to the simple absolute/percentage returns (FR-8.4). Where data is insufficient (single lump-sum holding), XIRR falls back to the simple CAGR/absolute return with a tooltip note.

### Investment Detail View

**FR-8.8:** Clicking a holding opens the detail view showing:
- Holding name, type, category
- Total units, buy price (average), current price
- Invested value, current value, absolute returns, percentage returns
- Gain/Loss indicator with color coding
- Purchase history table (all purchase lots with date, units, price, amount)
- Dividend/interest history table (all payouts received)
- Current price can be manually updated. Each update stores the previous price and date in `investment_price_history` (append-only) so return-calculation history is preserved.

### SIP Tracker

**FR-8.9:** User can add a SIP (Systematic Investment Plan) entry:
- Holding (required, FK → investments(id))
- SIP Amount (required, positive decimal)
- Frequency (required, enum: monthly / quarterly)
- Next Installment Date (required)
- Account ID (optional, FK → accounts(id), linked debit account)
- Status (active / paused / completed)
- Start Date
- End Date (or ongoing)

**FR-8.10:** SIPs appear on the dashboard with next installment date and amount. When the user logs an installment, it creates a transaction record and updates the holding's units/price.

### Dividend & Interest Logging

**FR-8.11:** User can record a dividend/interest payout with:
- Holding ID (required)
- Type (required, enum: dividend / interest / maturity_proceeds)
- Amount (required, positive decimal)
- Date (required)
- Linked Transaction (optional, FK → transactions(id))
- Notes (optional)

### Portfolio Snapshots

**FR-8.12:** A periodic snapshot records the portfolio's total value at a point in time. Snapshots are taken:
- Automatically when the user updates any holding's current price
- Manually on user request
- The snapshot stores: total_invested, total_current, snapshot_date (absolute/percentage return are derived on read)

**FR-8.13:** The portfolio value trend chart shows the line over time using snapshots. User can view 1M, 3M, 6M, 1Y, All time.

### Notifications

**FR-8.14:** Notifications include:
- **Maturity alert:** When an FD, bond, or fixed-term instrument is within 30 days of maturity date, a notification suggests reviewing reinvestment options
- **SIP due reminder:** 3 days before each SIP installment date if the SIP is active

### Export

**FR-8.15:** Export portfolio summary as CSV: Name, Type, Category, Units, Buy Price, Current Price, Invested, Current Value, Return %, Status.

**FR-8.16:** Export investment transaction/purchase history as CSV for any holding: Date, Type, Units, Price, Amount.

### Table: investment_price_history

Append-only per-holding price history — powers FR-8.8's "previous price and date" return-history requirement. Every manual `current_price` update appends one row (the previous price, dated the day before the update) **in the same write transaction** as the `investments` update.

| Column | Type | Constraints | Index | Description |
|--------|------|-------------|-------|-------------|
| id | UUID | PK, DEFAULT gen_random_uuid() | PRIMARY KEY | UUID |
| user_id | INTEGER | NOT NULL, FK → users(user_id) ON DELETE CASCADE | | Multi-user owner (covered by composite `idx_inv_price_date`) |
| investment_id | UUID | NOT NULL, FK → investments(id) ON DELETE CASCADE | INDEX idx_inv_price_inv | Parent holding |
| price | NUMERIC(12,4) | NOT NULL, CHECK(price > 0) | | Price per unit at that date (NULL-price instruments store valuation) |
| date | DATE | NOT NULL | | Effective date of this price point |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP | | When the row was written |

**Composite Indexes:**
```sql
-- Price history for a holding, sorted by date
CREATE INDEX idx_inv_price_date ON investment_price_history(user_id, investment_id, date);
```

**Performance Notes:**
- One row per price update. Weekly manual updates across 20 holdings × 52 weeks × 5 years = **~5,200 rows** per user — trivial size.
- "Previous price and date" reads are a `ORDER BY date DESC LIMIT 1` range scan on the composite index (< 1ms).

## Database Indexing Strategy

### Index Creation SQL

```sql
-- Investments (multi-user aware)
CREATE EXTENSION IF NOT EXISTS pg_trgm;  -- core PostgreSQL contrib; enables ILIKE '%...%' search
CREATE INDEX idx_inv_active_category ON investments(user_id, is_active, category);
-- Maturity alerts: user-scoped partial index (maturity alerts query user_id + maturity_date)
CREATE INDEX idx_inv_user_maturity ON investments(user_id, maturity_date) WHERE maturity_date IS NOT NULL;
-- Search: fuzzy name search via trigram (replaces the removed B-tree name index)
CREATE INDEX idx_inv_name_trgm ON investments USING GIN (name gin_trgm_ops);

-- Investment Transactions
CREATE INDEX idx_inv_transaction_inv ON investment_transactions(investment_id);
CREATE INDEX idx_inv_transaction_inv_date ON investment_transactions(user_id, investment_id, date DESC);
CREATE INDEX idx_inv_transaction_txn ON investment_transactions(transaction_id);

-- Investment Snapshots
CREATE INDEX idx_inv_snapshot_inv ON investment_snapshots(investment_id);
CREATE INDEX idx_inv_snapshot_inv_date ON investment_snapshots(user_id, investment_id, date);

-- Investment Price History (FR-8.8)
CREATE INDEX idx_inv_price_inv ON investment_price_history(investment_id);
CREATE INDEX idx_inv_price_date ON investment_price_history(user_id, investment_id, date);

-- Portfolio Snapshots
CREATE UNIQUE INDEX idx_ps_date ON portfolio_snapshots(user_id, date);

-- Dividend / Interest Records
CREATE INDEX idx_dir_inv ON dividend_income(investment_id);
CREATE INDEX idx_dir_inv_date ON dividend_income(user_id, investment_id, date DESC);
CREATE INDEX idx_dir_transaction ON dividend_income(transaction_id);

-- SIP Trackers
CREATE INDEX idx_st_inv ON sip_trackers(investment_id);
CREATE INDEX idx_st_next ON sip_trackers(next_date);
CREATE INDEX idx_st_account ON sip_trackers(account_id);
```

## Suggested Enhancements

1. **XIRR calculation** — Instead of simple absolute/percentage returns, implement XIRR (Extended Internal Rate of Return) that accounts for cash flow timing. This is the correct way to measure returns when money is added or withdrawn at different times. XIRR is widely used in India for mutual fund and portfolio performance reporting.

2. **SIP calculator** — A what-if calculator showing: "If you invest ₹10,000/month in this fund for 10 years at 12% expected return, your final value would be ~₹23.2L." Useful for goal-linked investment planning (bridges Module 5 Goals with Module 8 Investments).

3. **Portfolio rebalancing suggestions** — When actual asset allocation deviates from the user's target allocation by more than a configurable threshold (e.g., 5%), flag the deviation. For example: "Your equity allocation is at 72% vs target 60%. Consider rebalancing."

4. **Cost basis tracking for multiple lots** — Instead of storing a single average buy price, store each purchase lot separately with its own units, price, and date. When selling, the user can choose FIFO, LIFO, or specific lots. Essential for capital gains tax calculation (short-term vs long-term).

5. **Market price quick-update** — A single screen where the user can quickly update current prices for all active holdings at once. Type the new NAV/price, tap save, and all returns are recalculated. This reduces friction for manual price updates (since there's no auto-sync).

6. **SWP (Systematic Withdrawal Plan) tracker** — The inverse of SIP. Tracks recurring withdrawals from a mutual fund or investment. Useful for retirees or anyone using investments as an income source. Tracks withdrawal amount, frequency, remaining units, and projected depletion date.
