# C2. Notifications & Alerts Center Component

**Module Type:** Cross-Cutting Component (App Shell)  
**Build Phase:** Phase 2  
**Dependencies:** All modules (event sources), Auth & User Management (identity + email), `user_settings` (master notification switch)

---

## Purpose

Centralized feed for every alert, reminder, and warning generated across all modules. Lives in the app shell as a persistent notification bell (not a standalone page's only entry point, but includes a full center page). Every module already emits alerts in its own FRs (FR-3.10, FR-7.16, FR-8.14, FR-9.10, etc.); this component defines the single storage, delivery, preference, and email channel for all of them.

## Functional Requirements

### Bell & Unread Badge

**FR-C2.1:** The app header shows a bell icon with a badge counting unread (not dismissed, not expired) notifications. The badge updates in real time (re-fetch on navigation; SSE/polling optional).

### Slide-Out Panel & Center Page

**FR-C2.2:** Clicking the bell opens a slide-out panel with the 25 most recent notifications (title, message excerpt, module chip, relative timestamp, read/unread dot). A "See all" link opens the full Notifications Center page.

**FR-C2.3:** The center page renders all notifications with pagination (25/page) and the read/unread/dismissed state persisted per row.

### Filtering

**FR-C2.4:** Filters: type (warning / alert / reminder / insight / summary / info) and module source (account / transaction / budget / bills / subscription / goals / debt / tax / investment / net_worth / reports / calendar / system). Filters combine with AND and render as removable chips. Filtering is applied server-side via indexed queries (see Data Tables).

### Actions

**FR-C2.5:** Each notification supports:
- **Mark read** (single or "mark all as read")
- **Dismiss** — hides it from the default feed (still searchable in archive)
- **Take action** — navigate to the `deep_link` target (e.g., the budget screen for a 100% threshold alert, the bill detail for a due reminder)

**FR-C2.6:** Time-sensitive notifications (reminders, warnings) carry `expires_at`; expired rows are excluded from the feed and badge count automatically.

### Notification Preferences

**FR-C2.7:** The Settings screen (per `MoneyMind_Design_System.md` § Settings) shows a matrix of notification type × channel (in-app / email) with toggles. A master switch mirrors `user_settings.notifications_enabled` (global kill-switch); per-type toggles override within it. Defaults: all in-app ON, email OFF except bill reminders and weekly summary.

**FR-C2.8:** Preference changes upsert `notification_preferences` rows immediately; they take effect on the next trigger evaluation.

### Email Notifications

**FR-C2.9:** Email delivery is a background job (daily sweep + scheduled digests). Supported email types: bill reminder, subscription renewal reminder, budget threshold alert, weekly summary (Sunday), monthly report available (1st). Each send is recorded in `notification_emails` with status (queued / sent / failed) for observability.

**FR-C2.10:** Email content mirrors the in-app notification (title, message, module), plus a "View in MoneyMind" deep link.

### Notification History / Archive

**FR-C2.11:** The archive includes read, dismissed, and expired notifications. Search by title/message text (ILIKE on `title`/`message`, indexed) plus the type/module filters from FR-C2.4.

## Data Tables

### Table: notifications

The central feed table. Log-style (no version; `is_read`/`is_dismissed` are idempotent toggles). See `../data-tables-v2.md` § Component C2.

| Column | Type | Constraints | Index | Description |
|--------|------|-------------|-------|-------------|
| id | UUID | PK, DEFAULT gen_random_uuid() | PRIMARY KEY | UUID |
| user_id | INTEGER | NOT NULL, FK → users(user_id) ON DELETE CASCADE | INDEX idx_notif_user_read | Multi-user owner |
| type | TEXT | NOT NULL, CHECK(type IN ('warning','alert','reminder','insight','summary','info')) | INDEX idx_notif_type | Insight/summary reserved for AI phase |
| module | TEXT | NOT NULL, CHECK(module IN ('account','transaction','budget','bills','subscription','goals','debt','tax','investment','net_worth','reports','calendar','system')) | | Source module |
| title | TEXT | NOT NULL | | Short title |
| message | TEXT | NOT NULL | | Full message |
| data_payload | JSONB | | | Structured data for UI (e.g., budget_id, bill_id) |
| deep_link | TEXT | | | Route target for "take action" |
| priority | TEXT | NOT NULL DEFAULT 'medium', CHECK(priority IN ('low','medium','high')) | | Display priority |
| is_read | INTEGER | NOT NULL DEFAULT 0 | | Read status |
| is_dismissed | INTEGER | NOT NULL DEFAULT 0 | | Dismissed status |
| expires_at | TIMESTAMPTZ | | | Time-sensitive auto-expiry |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP | INDEX idx_notif_created | Created timestamp |

**Indexes:**
```sql
CREATE INDEX idx_notif_user_read ON notifications(user_id, is_read, created_at DESC) WHERE is_dismissed = 0;
CREATE INDEX idx_notif_type ON notifications(user_id, type, created_at DESC);
CREATE INDEX idx_notif_module ON notifications(user_id, module, created_at DESC);
CREATE INDEX idx_notif_created ON notifications(created_at);
```

**Performance Notes:**
- Bill/budget/subscription triggers produce a few rows per month; archive grows ~50–200 rows/year/user. All feed queries < 1ms.

## Database Indexing Strategy

### Index Creation SQL

```sql
CREATE INDEX idx_notif_user_read ON notifications(user_id, is_read, created_at DESC) WHERE is_dismissed = 0;
CREATE INDEX idx_notif_type ON notifications(user_id, type, created_at DESC);
CREATE INDEX idx_notif_module ON notifications(user_id, module, created_at DESC);
CREATE INDEX idx_notif_created ON notifications(created_at);
CREATE INDEX idx_nwm_user ON net_worth_milestones(user_id, is_active);
```

### Query Performance Benchmarks (Target)

| Query | Target Time | Index Used |
|-------|-------------|------------|
| Get unread count for badge | < 1ms | idx_notif_user_read (count on partial index) |
| Get feed (latest 25, user) | < 1ms | idx_notif_user_read |
| Filter feed by type | < 1ms | idx_notif_type |
| Filter feed by module | < 1ms | idx_notif_module |
| Mark all read | < 5ms | idx_notif_user_read (range update) |
| Insert trigger notification | < 5ms | PRIMARY KEY |
| Milestone crossing check (per daily snapshot) | < 1ms | idx_nwm_user |
| Send email batch (daily sweep) | < 50ms / 100 emails | idx_notif_user_read + idx_nwm_user |

## Suggested Enhancements

1. **Notification digest control** — Choose daily vs weekly email digest frequency per user.
2. **Quiet hours** — Suppress in-app/email notifications during user-defined quiet hours.
3. **Bulk actions** — Select-and-dismiss/archive multiple notifications at once.
4. **Priority sorting** — Optional "unread first" + "high priority first" sort modes beyond recency.
5. **AI insights (Phase 3)** — When the AI module ships, scheduled jobs (weekly summary, subscription audit, overspend prediction) write rows with type `insight`/`summary` into the same feed — no schema change required.
