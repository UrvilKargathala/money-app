# 9. Net Worth Tracker Module

**Module Type:** Wealth Overview  
**Build Phase:** Phase 2  
**Dependencies:** Module 1 (Account & Wallet), Module 2 (Transaction Engine), Module 5 (Savings & Goals), Module 6 (Debt & Loan Manager), Module 8 (Investment Tracker)

---

## Purpose

The Net Worth Tracker aggregates all assets and liabilities across the MoneyMind ecosystem to present a single, up‑to‑date view of the user's financial position. By pulling balances from accounts, investment values, goal savings, debts, and manually entered assets, the module computes **Net Worth = Total Assets – Total Liabilities** and visualises the progression over time.

## Functional Requirements

### Net Worth Calculation

**FR-9.1:** Net worth is **computed on read** — never stored incrementally. The current net worth aggregates: **Assets:** account balances (computed), investment current values, goal current amounts (computed on read), manual asset values. **Liabilities:** credit card balances, outstanding principal of each debt, any other user-defined liabilities. The nightly background job (FR-9.7) records the daily snapshot in `net_worth_snapshots` for charting; there is no on-every-change recalculation.

### Net Worth Trend Chart

**FR-9.2:** The module opens with a **hero net worth display**: the current net worth total with month-over-month and year-over-year change (absolute ₹ and %). Below it, a line chart with a date‑range selector. The chart pulls data from `net_worth_snapshots` and renders using Recharts. Hover tooltip shows:
- Date
- Net Worth total
- Assets total
- Liabilities total
- Percentage change from previous point

**FR-9.3:** The chart supports exporting the visual as PNG and the underlying data as CSV.

### Asset & Liability Breakdown

**FR-9.4:** A dedicated view presents two donut charts:
- **Assets:** Segmented by accounts, investments, goals, manual assets.
- **Liabilities:** Segmented by credit cards and debts.
- Clicking a segment drills down to a table of the underlying items.

### Manual Asset Entry

**FR-9.5:** Users can add a manual asset with fields:
- Name (required)
- Category (enum: property, vehicle, gold, other)
- Current valuation (required, positive decimal)
- Acquisition date (optional)
- Notes (optional)
- Depreciation method (optional, e.g., straight‑line, none)
- Depreciation schedule (if applicable)

**FR-9.6:** Manual assets contribute to the assets total and appear in the breakdown chart. Users can edit or delete manual assets; deletions remove the contribution from net worth calculations.

### Historical Snapshots

**FR-9.7:** A nightly background job records the net worth total in `net_worth_snapshots` (date, assets_total, liabilities_total; net worth derived on read). This enables fast retrieval for the trend chart without recomputing from all source tables.

### Export Net Worth Report

**FR-9.8:** Users can generate a PDF report that includes:
- Title page with date range.
- Net worth line chart.
- Asset and liability breakdown charts.
- Table listing all manual assets.
- Summary statistics (start value, end value, absolute & % change).

**FR-9.9:** The same data can be exported as CSV for external analysis.

### Milestone Notifications

**FR-9.10:** Users can define monetary milestones (e.g., INR 5 L, 10 L) via the `net_worth_milestones` table (see Component C2 and `data-tables-v2.md` § Component C2). When a daily snapshot crosses an active milestone, the Notifications Center creates an alert indicating the milestone has been reached; `notified_at` is stamped to prevent duplicates.

### Manual Asset List Filter

**FR-9.11:** The manual assets table (reached via the FR-9.4 donut drill-down) has a category filter: All / property / vehicle / gold / other. Filtering is applied client-side on the loaded list. No search box is needed at <20 assets per user.

### Assets vs Liabilities Ratio

**FR-9.12:** A side-by-side ratio bar compares Total Assets vs Total Liabilities for the current snapshot (e.g., assets ₹52L / liabilities ₹8L with a 6.5:1 ratio). The bar shows each side proportionally with the ratio labeled, plus the % change of both sides vs the previous month. Ratios use the same `net_worth_snapshots` data as the trend chart — no separate storage.

## Data Tables

### Table: net_worth_snapshots

Stores a daily snapshot of the user’s net worth for fast chart rendering and historical analysis.

| Column | Type | Constraints | Index | Description |
|--------|------|-------------|-------|-------------|
| id | UUID | PK, DEFAULT gen_random_uuid() | PRIMARY KEY | UUID |
| user_id | INTEGER | NOT NULL, FK → users(user_id) ON DELETE CASCADE | INDEX idx_nw_user | Multi-user owner |
| date | DATE | NOT NULL | COMPOSITE UNIQUE (user_id, date) via `idx_nw_date` | Snapshot date (one per user per day) |
| assets_total | NUMERIC(12,2) | NOT NULL | | Sum of all asset values on this date |
| liabilities_total | NUMERIC(12,2) | NOT NULL | | Sum of all liability values on this date |
| version | INTEGER | NOT NULL DEFAULT 1 | | Optimistic lock |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP | | Created timestamp |
| updated_at | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP | | App-managed timestamp |

> `net_worth` was removed as a stored column — derived: `assets_total − liabilities_total` computed on read (or a `GENERATED` column).

**Unique constraint:** `UNIQUE (user_id, date)` (see canonical schema).

**Performance Notes:**
- One row per user per day. For a 10‑year history this is ~3,650 rows per user – trivial size.
- Index `(user_id, date)` enables range scans for the trend chart (`WHERE user_id = ? AND date BETWEEN ? AND ?`).
- Insertion occurs nightly via a background job; insert time < 5 ms.

### Table: manual_assets

Allows users to record non‑tracked assets such as property, vehicles, gold, etc.

| Column | Type | Constraints | Index | Description |
|--------|------|-------------|-------|-------------|
| id | UUID | PK, DEFAULT gen_random_uuid() | PRIMARY KEY | UUID |
| user_id | INTEGER | NOT NULL, FK → users(user_id) ON DELETE CASCADE | INDEX idx_ma_user | Multi-user owner |
| name | TEXT | NOT NULL | INDEX idx_ma_name | Asset name (e.g., "3‑BHK Apartment") |
| category | TEXT | NOT NULL, CHECK(category IN ('property','vehicle','gold','other')) | INDEX idx_ma_category | Asset category |
| valuation | NUMERIC(12,2) | NOT NULL | | Current market value |
| acquisition_date | DATE | | | Date asset was acquired |
| depreciation_method | TEXT | | | e.g., "straight_line", "none" |
| depreciation_schedule | JSONB | | | JSON blob describing schedule if applicable |
| notes | TEXT | | | Optional user notes |
| version | INTEGER | NOT NULL DEFAULT 1 | | Optimistic lock |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP | | Created timestamp |
| updated_at | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP | | App-managed timestamp |

**Performance Notes:**
- Typically < 20 manual assets per user, so all queries are sub‑millisecond.
- Indexes on `user_id`, `name`, and `category` support asset list filtering and search (client-side filters on the loaded list; no search box needed at this scale).

## Database Indexing Strategy

### Index Creation SQL

```sql
-- Net Worth Snapshots
CREATE UNIQUE INDEX idx_nw_date ON net_worth_snapshots(user_id, date);
CREATE INDEX idx_nw_user ON net_worth_snapshots(user_id);

-- Manual Assets
CREATE INDEX idx_ma_user ON manual_assets(user_id);
CREATE INDEX idx_ma_name ON manual_assets(name);
CREATE INDEX idx_ma_category ON manual_assets(category);
```

### Query Performance Benchmarks (Target)

| Query | Target Time | Index Used |
|-------|-------------|------------|
| Get net worth trend for date range (user) | < 1ms | idx_nw_date (range scan) |
| Insert daily net worth snapshot | < 5ms | idx_nw_date (unique check) |
| Get all manual assets (user) | < 0.5ms | idx_ma_user |
| Filter manual assets by category (user) | < 0.5ms | idx_ma_category (client-side filter at current scale) |

## Suggested Enhancements

1. **Multi‑Currency Support** – Add a `currency` column to `manual_assets` and store a `conversion_rate_to_inr` in the snapshot job to automatically convert foreign‑currency assets to INR for net worth aggregation.
2. **Inflation‑Adjusted Net Worth** – Store CPI index values per month and compute an inflation‑adjusted net worth metric for long‑term wealth tracking.
3. **Depreciation Auto‑Calculation** – For assets with a depreciation schedule, run a nightly job that updates the `valuation` field based on the chosen method, keeping net worth realistic.
4. **Goal‑Linked Net Worth Projection** – Integrate with the Goals module to forecast future net worth based on planned contributions and debt repayments, presenting a "Projected Net Worth" line on the chart.
5. **Export Enhancements** – Include a downloadable JSON version of the net worth time series for users who wish to import into external analysis tools (e.g., Excel, Power BI).
6. **Custom Milestone Management UI** – Provide a UI screen where users can define, edit, and delete monetary milestones, with optional reminder frequencies (e.g., weekly, monthly).
