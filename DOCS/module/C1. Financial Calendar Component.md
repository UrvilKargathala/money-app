# C1. Financial Calendar Component

**Module Type:** Cross-Cutting Component (App Shell / Dashboard Widget)  
**Build Phase:** Phase 2  
**Dependencies:** Module 2 (Transaction Engine — recurring templates), Module 4 (Bills & Subscriptions), Module 5 (Savings & Goals), Module 6 (Debt & Loan — amortization schedule), Module 8 (Investment Tracker — SIPs, maturities), Module 7 (Tax Planning — deadlines), Component C2 (Notifications — stress/conflict warnings)

---

## Purpose

A unified calendar of all scheduled financial events across every module. The calendar is **derived** — events are computed on read from existing tables, not stored as event rows. Only user-defined custom events persist (`calendar_events`). It also powers the daily cash flow projection (predicted balance after scheduled events per account).

## Functional Requirements

### Monthly Calendar Grid

**FR-C1.1:** The calendar shows a standard monthly grid (week starts Monday). Each date cell lists the day's financial events as compact chips (icon + short label + amount). Dates with events show a count badge; the current day is highlighted.

**FR-C1.2:** Month navigation: previous/next month arrows, a month picker, and a "Today" shortcut. The default view is the current month.

### Color-Coded Events

**FR-C1.3:** Event colors (per MoneyMind_Feature_List_v3, C1):

| Color | Event Type | Source |
|-------|-----------|--------|
| Green | Income (salary, expected credits) | `recurring_transaction_templates` (type = income) |
| Red | Bill due | `bills` (due_day) |
| Orange | Subscription renewal | `subscriptions` (next_renewal_date) |
| Purple | EMI deduction | `amortization_schedule` (scheduled_date) |
| Blue | SIP installment | `sip_trackers` (next_date) |
| Gold | Goal milestone / target date | `goals` (target_date) |
| Dark red | Tax deadline | Tax deadline registry (see FR-C1.6) |
| Grey | Custom event | `calendar_events` |

**FR-C1.4:** Derived event mapping (all read-only, computed per render):

| Source Table | Event Date | Label | Amount |
|--------------|-----------|-------|--------|
| `bills` | due_day of current month | Bill name | `amount` or `estimated_amount` |
| `subscriptions` | next_renewal_date | Service name | `amount` |
| `recurring_transaction_templates` (income) | next_due_date | Description | `amount` |
| `amortization_schedule` | scheduled_date | Debt name + "EMI" | `emi_amount` |
| `sip_trackers` | next_date | Holding name + "SIP" | `amount` |
| `investments` | maturity_date (≤ 30 days out) | Holding name + "Maturity" | `current_value` (informational) |
| `goals` | target_date | Goal name + "Target Date" | `target_amount` |
| Tax deadlines | fixed dates | See FR-C1.6 | — |

**FR-C1.5:** Bills whose due day (e.g., 31st) does not exist in a month use the last day of that month (inherits Module 4 behavior).

### Tax Deadline Registry

**FR-C1.6:** Fixed tax deadlines appear each year:
- **Jul 31** — ITR filing deadline (current assessment year)
- **Jun 15 / Sep 15 / Dec 15 / Mar 15** — advance tax due dates (if enabled in settings)
- **Apr 1** — new financial year begins (FY selector auto-advances, per Module 7)

Deadlines are seeded as app config (not DB rows); they are rendered by the calendar service.

### Day Detail Panel

**FR-C1.7:** Clicking a date opens a detail panel listing all events for that date: event type, label, amount, linked account (where applicable), and status (e.g., bill status from `bills.current_period_status`, subscription status). Each event deep-links to its source module screen (cross-ref Component C2 `deep_link` pattern).

### Upcoming Events List

**FR-C1.8:** A list view shows the next 7 days and next 30 days of events in chronological order, grouped by day, with a per-day outgoing/incoming total. A combined 30-day net cash flow figure is shown at the top.

### Daily Cash Flow Projection

**FR-C1.9:** For each account, the projected balance on day D = current balance (computed on read) − Σ scheduled outflows (bills, subscriptions, EMIs, SIPs, custom expense events) + Σ scheduled inflows (recurring income, custom income events) from today through D. Projection is computed for today, +7, and +30 days.

**FR-C1.10:** Days where the projected balance drops below ₹0 (or below the account's configured minimum balance threshold, Module 1 enhancement) are flagged in red on the calendar. This is the manual, AI-free version of the "cash flow stress detection" AI feature (reserved for the AI phase).

### Custom Events

**FR-C1.11:** User can add a custom event with: title (required), date (required), optional end date (multi-day), type (reminder / income / expense / other), amount (optional, income/expense only), linked account (optional), color, and notes.

**FR-C1.12:** Custom events of type income/expense with a linked account participate in the daily cash flow projection (FR-C1.9). Reminders do not affect projection. User can edit/delete custom events; deleting removes them from all views.

## Data Tables

### Table: calendar_events

User-defined custom events. **All other calendar events are derived on read and never stored.** See `../data-tables-v2.md` § Component C1.

| Column | Type | Constraints | Index | Description |
|--------|------|-------------|-------|-------------|
| id | UUID | PK, DEFAULT gen_random_uuid() | PRIMARY KEY | UUID |
| user_id | INTEGER | NOT NULL, FK → users(user_id) ON DELETE CASCADE | INDEX idx_ce_user_date | Multi-user owner |
| title | TEXT | NOT NULL | | Event label |
| event_date | DATE | NOT NULL | | Event date (covered by `idx_ce_user_date`) |
| end_date | DATE | | | Optional multi-day span end |
| event_type | TEXT | NOT NULL DEFAULT 'reminder', CHECK(event_type IN ('reminder','income','expense','other')) | | Event classification |
| amount | NUMERIC(12,2) | | | Amount (income/expense only) |
| account_id | UUID | FK → accounts(id) | | Linked account (projection) |
| color | TEXT | | | Hex color override |
| notes | TEXT | | | Optional user notes |
| version | INTEGER | NOT NULL DEFAULT 1 | | Optimistic lock |
| created_by | INTEGER | FK → users(user_id) | | Audit |
| updated_by | INTEGER | FK → users(user_id) | | Audit |
| deleted_at | TIMESTAMPTZ | | | Soft delete |
| deleted_by | INTEGER | FK → users(user_id) ON DELETE SET NULL | | Who deleted |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP | | Created timestamp |
| updated_at | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP | | App-managed timestamp |

**Indexes:**
```sql
CREATE INDEX idx_ce_user_date ON calendar_events(user_id, event_date);
```

**Performance Notes:**
- Custom events: 0–50 per user lifetime. Trivial size.
- The calendar service composes derived events (FR-C1.4) + custom events in a single request; all source queries use existing module indexes (< 1ms each).

## Suggested Enhancements

1. **Week view** — Add a week strip view alongside month grid for dense schedules.
2. **Event snooze/dismiss** — Allow dismissing a derived event (e.g., "bill already paid") for the current period; store the dismissal (per-user override) in a small `calendar_event_dismissals` table.
3. **iCal export** — Export the month's events (derived + custom) as an `.ics` file for external calendars.
4. **Recurring custom events** — Extend `calendar_events` with a simple recurrence (weekly/monthly) for custom events; note this would require a recurrence rule column.
5. **Cash flow stress detection (AI)** — Reserved for the AI phase: analyze projected balance clusters and generate warnings with suggested payment-date shifts (MoneyMind_Feature_List_v3 AI #31).
6. **Date conflict detection (AI)** — Reserved for the AI phase: flag multiple large payments on the same date and suggest spreading them (AI #32).
