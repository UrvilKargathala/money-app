# C3. Data Export Component

**Module Type:** Cross-Cutting Component  
**Build Phase:** Phase 1 (basic CSV) + Phase 2 (full PDF + archive)  
**Dependencies:** All modules (data sources), Module 10 (report_exports for dashboard PDFs), Auth & User Management (GDPR deletion)

---

## Purpose

Provides per-module CSV and PDF exports, date-stamped file naming, a full-data archive export, and the GDPR account deletion flow. Every module already specifies its own export FRs (FR-1.16, FR-2.13/2.11, FR-3.19, FR-4.17, FR-5.15, FR-6.22, FR-7.17, FR-8.15, FR-9.8, FR-10.9); this component defines the shared export job pipeline, naming convention, archive format, and deletion semantics.

## Functional Requirements

### Per-Module CSV Export

**FR-C3.1:** Every module screen with a list (Accounts, Transactions, Budgets, Bills, Subscriptions, Goals, Debt, Tax, Investments, Net Worth, Secure Notes header rows) has an "Export CSV" button. Each module's export column set is defined in that module's own FRs.

**FR-C3.2:** CSV exports are generated from a server-side query scoped to `user_id` (RLS applies) and streamed to the client. Amounts are rendered as plain numbers (no ₹ symbol) with two decimals; dates as ISO `YYYY-MM-DD`; percent fields with one decimal.

**FR-C3.3:** Every export request creates a `data_export_jobs` row (status = queued → processing → completed/failed) for auditability. Failures record `error_message` and surface a toast to the user with a retry button.

### Per-Module PDF Export

**FR-C3.4:** Modules with chart/report capabilities (Budget, Debt, Investments, Net Worth, Reports) expose a "Export PDF" button that renders the current view (with charts) via the PDF pipeline defined in Module 10 (jsPDF / @react-pdf/renderer). Totals and summaries are included per module FRs.

**FR-C3.5:** Dashboard report PDFs (Module 10) are additionally recorded in `report_exports`; module PDFs (FR-C3.4) are recorded in `data_export_jobs` only.

### File Naming Convention

**FR-C3.6:** File names follow `MoneyMind_<Module>_<YYYY-MM-DD>.<ext>` where `<Module>` is the singular module name (Transactions, Budgets, Bills, Subscriptions, Goals, Debt, Tax, Investments, NetWorth, Reports, Notes). Full archive: `MoneyMind_FullBackup_<YYYY-MM-DD>.zip`. Duplicate names within the same day get a time suffix (`_0930`).

### Full Data Export

**FR-C3.7:** The "Export all data" action (Settings → Data) generates a single `.zip` archive containing:
- Per-module CSV files using the same naming convention (FR-C3.6)
- A JSON manifest (`manifest.json`) with schema version, export timestamp, and per-module row counts
- (Phase 2) A PostgreSQL portable dump (`pg_dump --data-only`) or equivalent JSON export for full restore

**FR-C3.8:** Full export runs as a background job (large datasets get a progress indicator with file size estimate — per BRD FR-C3.5). Completed archives are stored under a per-user storage prefix; download links expire after 24 hours.

### Account Data Deletion (GDPR)

**FR-C3.9:** Account deletion (Settings → Danger zone) requires the user to type their password confirmation. The flow:
1. Writes a `users.deleted_at` soft-delete marker immediately (user can cancel within a 30-day grace window)
2. Permanently purges all user-owned rows after the grace period via the FK `ON DELETE CASCADE` graph (accounts, transactions, budgets, bills, goals, debts, investments, tax, net worth, notes, notifications, calendar events, exports, audit-scoped rows with `user_id`)
3. Emails a confirmation + exports a final data copy link before purge (optional)

**FR-C3.10:** Deleting the account logs a final `audit_logs` entry (user_id preserved via `ON DELETE SET NULL` for the actor column, `record_id` = user_id) so the deletion itself is auditable.

## Data Tables

### Table: data_export_jobs

Audit log of every export request. Log-style table (no version). See `../data-tables-v2.md` § Component C3.

| Column | Type | Constraints | Index | Description |
|--------|------|-------------|-------|-------------|
| id | UUID | PK, DEFAULT gen_random_uuid() | PRIMARY KEY | UUID |
| user_id | INTEGER | NOT NULL, FK → users(user_id) ON DELETE CASCADE | INDEX idx_dej_user | Multi-user owner |
| export_type | TEXT | NOT NULL, CHECK(export_type IN ('csv','pdf','full_archive')) | | Export kind |
| scope | TEXT | NOT NULL, CHECK(scope IN ('module','all')) | | Single module or full archive |
| module_name | TEXT | | | Target module (NULL for `all`) |
| date_range_start / end | DATE | | | Optional range filter |
| status | TEXT | NOT NULL DEFAULT 'queued', CHECK(status IN ('queued','processing','completed','failed')) | INDEX idx_dej_status | Lifecycle |
| file_path | TEXT | | | Storage path of generated file |
| file_type | TEXT | CHECK(file_type IN ('csv','pdf','zip','sql','json')) | | Output format |
| row_count | INTEGER | | | Rows exported |
| file_size | INTEGER | | | Bytes |
| error_message | TEXT | | | Failure reason |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP | INDEX idx_dej_created | Created timestamp |

**Indexes:**
```sql
CREATE INDEX idx_dej_user ON data_export_jobs(user_id, created_at DESC);
CREATE INDEX idx_dej_status ON data_export_jobs(user_id, status);
```

**Performance Notes:**
- A few exports per week per user; 100+ only for heavy exporters. All queries < 1ms.

> **Related tables:** `report_exports` (Module 10) tracks dashboard template PDFs; `data_export_jobs` tracks everything else (module CSVs/PDFs + full archives). Both are log-style.

## Database Indexing Strategy

### Index Creation SQL

```sql
CREATE INDEX idx_dej_user ON data_export_jobs(user_id, created_at DESC);
CREATE INDEX idx_dej_status ON data_export_jobs(user_id, status);
```

### Query Performance Benchmarks (Target)

| Query | Target Time | Index Used |
|-------|-------------|------------|
| Get my recent exports | < 1ms | idx_dej_user |
| Get running jobs for a user | < 1ms | idx_dej_status |
| Insert export job | < 5ms | PRIMARY KEY |
| Update job status on completion | < 5ms | PRIMARY KEY |

## Suggested Enhancements

1. **Scheduled exports** — Cron-based recurring exports (monthly CSV snapshot emailed to the user). Mirrors Module 10's scheduled-report enhancement.
2. **Excel export** — Per-module `.xlsx` output with formatted sheets (Phase 3, power users).
3. **Encrypted archive** — Optional password-protected zip for the full-data export.
4. **Incremental backup** — Export only data changed since the last backup, for very large datasets.
5. **Export preview** — Show the export's row count and estimated file size in the confirmation dialog before generation.
