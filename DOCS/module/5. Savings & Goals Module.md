# 5. Savings & Goals Module

**Module Type:** Target-Based Savings  
**Build Phase:** Phase 2  
**Dependencies:** Module 1 (Account & Wallet), Module 2 (Transaction Engine)

---

## Purpose

Target-based savings tracking. Users define financial goals (emergency fund, vacation, down payment, new laptop, etc.) with target amounts and dates, then track progress through manual contributions. The module answers: "Am I saving enough to reach my goals on time?"

## Functional Requirements

### Goal Creation & Management

**FR-5.1:** User can create a goal with:
- Name (required, e.g., "Emergency Fund", "Thailand Trip")
- Target Amount (required, positive decimal)
- Target Date (required, future date)
- Priority (required, enum: high / medium / low)
- Linked Account (optional, which account the savings are in)
- Notes (optional)
- Color (optional, for UI display)

**FR-5.2:** On creation, the system calculates and displays:
- Required monthly contribution: `target_amount / months_remaining`
- Percentage of target if saved at current rate: `(current_amount + monthly_contribution × months_remaining) / target_amount × 100`
- Feasibility indicator: green (on track), yellow (slightly behind), red (significantly behind)

**FR-5.3:** User can edit goal name, target amount, target date, priority, and linked account. Changes to target amount or date recalculate the required monthly contribution.

**FR-5.4:** User can mark a goal as:
- **Active** — currently being worked toward (default)
- **Paused** — temporarily on hold, goal is hidden from active dashboard but not deleted
- **Completed** — target amount reached or user marks it done. A congratulatory message is shown with: total saved, time taken, and average monthly contribution.

**FR-5.5:** User can delete a goal. A confirmation dialog warns: "This will delete the goal and all its contribution history."

### Goal Dashboard

**FR-5.6:** The goal dashboard shows:
- Summary card at top: total saved across all goals / total target across all goals / overall completion %
- Each active goal as a card showing:
  - Name, icon/color, priority badge
  - Progress bar: current amount / target amount (e.g., "₹45,000 / ₹1,00,000")
  - Percentage complete
  - Timeline indicator: "X months remaining"
  - Monthly contribution needed vs planned: "Need ₹8,300/mo | Saving ₹5,000/mo"
  - Status indicator: on track (green check), behind (yellow warning), critical (red alert)

**FR-5.7:** Goals are sorted by target date ascending (most urgent first), then by priority.

### Contributions

**FR-5.8:** User can log a contribution with:
- Amount (required, positive decimal)
- Date (required, defaults to today)
- Notes (optional, e.g., "March savings transfer")
- Link to Transaction (optional, can link to an existing transaction or create a new transfer transaction)

**FR-5.9:** Contribution list for each goal shows: date, amount, linked transaction reference, notes, running total (computed on read).

**FR-5.10:** User can edit or delete a contribution. Deleting reduces the goal's current amount (derived on read as `SUM(goal_contributions.amount)`).

### Goal Templates

**FR-5.11:** Predefined goal templates available on goal creation:

| Template | Target Amount | Target Date | Description |
|----------|--------------|-------------|-------------|
| Emergency Fund | 6× Monthly Expenses | 12 months away | 6 months of living expenses saved |
| Vacation | ₹50,000 - ₹2,00,000 | 6-12 months away | Trip fund |
| New Laptop/Phone | ₹50,000 - ₹1,50,000 | 3-6 months away | Gadget upgrade |
| Down Payment | 20% of Property Value | 3-5 years away | Home down payment |
| Wedding | ₹5,00,000 - ₹20,00,000 | 1-3 years away | Wedding fund |
| Custom | User-defined | User-defined | Blank template |

**FR-5.12:** Templates auto-fill suggested amounts based on the user's average monthly spending and income. User can override all values.

### Goal Snapshots (Progress Charting)

**FR-5.13:** A periodic snapshot of goal progress is recorded (weekly). This enables the progress-over-time chart without recalculating from all contributions.

**FR-5.14:** Progress chart shows: goal amount (horizontal line), actual saved so far (line/area graph), projected trajectory (dotted line from current to target).

### Export

**FR-5.15:** Export all goals as CSV with: Name, Target Amount, Current Amount, Progress %, Target Date, Status, Priority.

**FR-5.16:** Export contribution history for any goal as CSV: Date, Amount, Notes.

**FR-5.17:** Export progress chart as PDF for any goal.

### Goal List Filters

**FR-5.18:** The goal dashboard has status filter tabs: Active / Paused / Completed (formalizes F6). The default view shows Active only; the summary cards (FR-5.6) reflect the active tab's set. Filtering is applied client-side on the loaded list.

**FR-5.19:** User can filter goals by priority (multi-select): high / medium / low. Filters combine with AND logic and render as removable chips (mirroring FR-2.18). No search box is needed at 3–10 active goals per user.

### Milestone Tracking

**FR-5.20:** Each goal tracks milestones at 25%, 50%, 75%, and 100% of target. When a contribution crosses a milestone threshold, the system:
- Inserts a `goal_milestones` row (goal_id, milestone_pct, reached_date) — unique per (goal, milestone)
- Emits a congratulatory notification via the Notifications Center (Component C2), guarded by `goal_milestones.notified_at` so it fires once per milestone
- Displays the milestone strip on the goal card: 4 dots/segments with the reached date tooltip (e.g., "50% — reached Aug 3, 2026")

**FR-5.21:** Milestones are computed on read from `current_amount / target_amount`; the row is written the first time the threshold is crossed. If a contribution is later deleted and the goal drops below a milestone, the milestone row is removed (and can re-fire when crossed again).

### Projected Completion Date

**FR-5.22:** The goal card shows a projected completion date computed from the current contribution rate: `months_to_finish = ceil((target_amount − current_amount) / avg_monthly_contribution)` applied to today, where `avg_monthly_contribution` is the average of the last 3 months' contributions (or the user's monthly plan if no history). If the rate is zero, it shows "No active contributions". The projection is displayed next to the target date and drives the FR-5.2 feasibility indicator.

## Data Tables

### Table: goals

The primary table storing goal configurations and current progress.

|--------|------|-------------|-------|-------------|

| name | TEXT | NOT NULL | | Goal name |
| target_amount | NUMERIC(12,2) | NOT NULL, CHECK(target_amount > 0) | | Target savings amount |
| target_date | DATE | NOT NULL | | Target completion date (covered by composite) |
| priority | TEXT | NOT NULL DEFAULT 'medium', CHECK(priority IN ('high','medium','low')) | | Goal priority |
| status | TEXT | NOT NULL DEFAULT 'active', CHECK(status IN ('active','paused','completed')) | | Current status (covered by composite) |
| account_id | UUID | FK → accounts(id) | INDEX idx_goal_account | Linked savings account |
| color | TEXT | | | Hex color for UI |
| notes | TEXT | | | Optional user notes |
| template_used | TEXT | | | Template name if created from template |
| completed_at | DATE | | | Date goal was completed |
| version | INTEGER | NOT NULL DEFAULT 1 | | Optimistic lock |
| created_by | INTEGER | FK → users(user_id) | | Audit |
| updated_by | INTEGER | FK → users(user_id) | | Audit |
| deleted_at / deleted_by | TIMESTAMPTZ / INTEGER | FK → users(user_id) | | Soft delete |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP | | Created timestamp |
| updated_at | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP | | App-managed timestamp |

**Composite Indexes:**
```sql
-- Primary dashboard query: all active goals for a user sorted by target date
CREATE INDEX idx_goal_active_date ON goals(user_id, status, target_date);
```

> **`current_amount` was removed** — derived on read as `SUM(goal_contributions.amount) WHERE goal_id = ?` (the Account module's "balance is computed on read, never stored" pattern; no drift, no separate recalculation step). "Current amount" below always means this derived value.

**Performance Notes:**
- Typical usage: 3-10 goals at any time. Even over 20 years, a user might have 50-100 completed goals
- The `user_id + status + target_date` composite index makes the dashboard query instant (< 0.5ms)

## Database Indexing Strategy

### Index Creation SQL

```sql
-- Goals table (multi-user aware)
CREATE INDEX idx_goal_account ON goals(account_id);
CREATE INDEX idx_goal_active_date ON goals(user_id, status, target_date);

-- Goal Contributions
CREATE INDEX idx_gc_goal ON goal_contributions(goal_id);
CREATE INDEX idx_gc_goal_date ON goal_contributions(user_id, goal_id, date);
CREATE INDEX idx_gc_transaction ON goal_contributions(transaction_id);

-- Goal Templates (system templates: unique name, NULL user_id;
-- user-created templates: unique name per user)
CREATE UNIQUE INDEX idx_gt_system_name ON goal_templates(name) WHERE user_id IS NULL;
CREATE UNIQUE INDEX idx_gt_user_name ON goal_templates(user_id, name) WHERE user_id IS NOT NULL;

-- Goal Snapshots
CREATE INDEX idx_gs_goal ON goal_snapshots(goal_id);
CREATE UNIQUE INDEX idx_gs_goal_date ON goal_snapshots(user_id, goal_id, date);

-- Goal Milestones (F12)
CREATE UNIQUE INDEX idx_gm_goal ON goal_milestones(user_id, goal_id, milestone_pct);
```

### Query Performance Benchmarks (Target)

| Query | Target Time | Index Used |
|-------|-------------|------------|
| Get all active goals sorted by urgency (user) | < 0.5ms | idx_goal_active_date |
| Get goal by ID (scoped to user) | < 0.5ms | PRIMARY KEY (user scoping via RLS) |
| Get contribution history for a goal (user) | < 1ms | idx_gc_goal_date |
| Calculate total saved across all active goals (user) | < 0.5ms | idx_goal_active_date (aggregate) |
| Log a contribution (insert only; goal amount derived on read) | < 2ms | PRIMARY KEY + idx_gc_goal |
| Get progress snapshots for chart (user) | < 1ms | idx_gs_goal_date |
| Get completed goals count (user) | < 0.5ms | idx_goal_active_date (filter 'completed') |
| Export all goals as CSV (user) | < 3ms | idx_goal_active_date |

## Suggested Enhancements

1. **Auto-contributions** — Allow users to set up recurring contributions to goals on a schedule (e.g., "Transfer ₹5,000 to Emergency Fund on the 1st of every month"). Creates a transaction automatically. This is essentially a recurring transaction linked specifically to a goal.

2. **Goal rebalancing** — If a user has multiple goals and gets a windfall (bonus, tax refund), a "Distribute" feature suggests how to split the extra money across goals proportionally or by priority.

3. **Milestone notifications** — When a goal reaches 25%, 50%, 75%, and 100%, show a congratulatory notification with a motivational message. This small dopamine hit keeps users engaged with their savings.

4. **Goal-linked budgets** — When creating a goal, the system can suggest reducing a discretionary category (e.g., "Reduce Dining Out from ₹8,000 to ₹5,000 to free up ₹3,000/month for your Vacation goal"). This would bridge with the Budget Module (Module 3).

5. **Goal prioritization + snowball method** — Allow users to rank goals in order of importance. When extra money is available (from budget underspend or unexpected income), the system suggests applying it to the highest-priority goal first (like the debt snowball method, but for savings).

6. **Visual goal board** — A kanban-style or vision-board view of all goals with cover images (user can upload a photo of their dream home, vacation destination, etc.). Makes the financial goal feel more tangible.
