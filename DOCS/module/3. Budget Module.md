# 3. Budget Module

**Module Type:** Financial Planning & Control  
**Build Phase:** Phase 1  
**Dependencies:** Module 1 (Account & Wallet), Module 2 (Transaction Engine)

---

## Purpose

The Budget Module provides financial planning and control. Users set spending limits per category and track actual spending against budgets in real-time. It answers the core question: "Am I spending too much in any area?" with visual feedback and configurable alerts.

## Functional Requirements

### Budget Creation & Management

**FR-3.1:** User can create a budget with the following fields:
- Category (required, dropdown of all leaf-level categories, or "Overall" for total budget)
- Amount (required, positive decimal)
- Period (required, enum: monthly / weekly, default: monthly)
- Alert thresholds (checkboxes: 50%, 80%, 100%, all enabled by default)
- Month/Year (defaults to current month)

**FR-3.2:** User can create multiple budgets for different categories. Only one budget per category per month is allowed.

**FR-3.3:** User can edit a budget's amount and alert thresholds at any time. Changes apply to the current period forward. Past months' budgets are immutable (historical record).

**FR-3.4:** User can delete a budget. Deletion removes the budget for all time periods. A confirmation dialog warns: "This will remove the budget for all months. Past budget history will be lost."

**FR-3.5:** Budgets are automatically carried forward to the next month if not explicitly ended. The same amount is used unless the user provides a different amount for the new month.

### Budget Dashboard

**FR-3.6:** The budget dashboard shows a summary card for each budgeted category:
- Category name and icon
- Spent amount / Budgeted amount (e.g., "₹12,500 / ₹15,000")
- Percentage used (e.g., "83%")
- Progress bar with color coding: green (0-50%), yellow (50-80%), orange (80-100%), red (100%+)
- Remaining amount (budget - spent)
- Remaining days in the period
- Daily spending limit for remaining days to stay within budget

**FR-3.7:** Budgets are sorted by utilization percentage descending (most over-budget first).

**FR-3.8:** Categories without budgets are shown in a separate "Unbudgeted" section with their current month spend and a "Create Budget" button.

**FR-3.9:** An overall summary card shows:
- Total budgeted amount across all categories
- Total spent amount
- Overall utilization percentage
- Over-budget count (how many categories exceeded budget)

### Budget Alerts

**FR-3.10:** When a budget crosses a configured threshold (50%, 80%, 100%), an alert is generated in the Notifications & Alerts Center.

**FR-3.11:** At 100%, the budget card border turns red and shows "Over budget by ₹X,XXX" prominently.

**FR-3.12:** The "remaining days" calculation updates daily. The "daily spending limit" is calculated as: (remaining amount / remaining days). If remaining days = 0, shows "Today is the last day — spend ₹0 to stay within budget."

### Month-over-Month Comparison

**FR-3.13:** User can select a budget category and view a bar chart comparing budgeted vs actual for the last 6 or 12 months. **Module 3 owns the budget-vs-actual computation** (actual spend per category is derived from transactions/splits, budgeted from `budgets`); Module 10's FR-10.4 consumes this computed metric for visualization only — see Module 10.

**FR-3.14:** Each month shows two bars side-by-side: budgeted (light shade) and actual (dark shade). Over-budget months are highlighted in red.

### Budget Rollover

**FR-3.15:** User can enable rollover on a budget. If enabled, unused budget amount at the end of the month is added to the next month's budget for that category.

**FR-3.16:** Rollover amount is displayed separately: "This month's budget: ₹15,000 (+ ₹2,000 rolled over from last month)."

**FR-3.15a (over-budget / negative remaining):** Rollover applies only to **unused** budget. If the user is over budget (spent > budgeted, remaining negative), **no amount rolls over** — a negative remaining is capped at zero and never reduces the next month's budget.

**FR-3.15b (compounding):** Rollover compounds across consecutive months. Month 1's surplus rolls into month 2's budget; month 2's surplus (budget + rolled-over amount − spend) rolls into month 3, and so on. Each transfer is recorded as a `budget_rollovers` row so the history is auditable.

**FR-3.15c (disabling rollover mid-chain):** Disabling rollover stops future accumulation — no further rollover rows are created from that month onward — but amounts already applied to the current month's budget stay applied. Previously generated `budget_rollovers` rows are retained.

**FR-3.15d (deleting a budget with pending rollover):** Deleting a budget cancels any rollover it has already applied to the next month (the applied amount is revoked from that month's budget) and prevents its own future rollover from being created. Deleting the *receiving* budget leaves the rolled-over amount's source row intact but the applied amount is discarded.

### Budget Templates

**FR-3.17:** User can save the current set of budgets as a template with a name (e.g., "Standard Month", "Festival Season").

**FR-3.18:** User can apply a template — it creates budgets for the current month based on the template values.

### Export

**FR-3.19:** User can export the budget dashboard as a PDF report showing: all budgeted categories with spent/remaining/progress, unbudgeted categories, and overall summary.

**FR-3.20:** User can export budget vs actual comparison data as CSV for the selected month.

### Budget Dashboard Filters

**FR-3.21:** The budget dashboard has an explicit Month/Year selector in the action bar (formalizes the month/year navigation from FR-3.1/FR-3.6). Selecting a different month re-renders the dashboard for that period.

**FR-3.22:** The dashboard has a view filter: All / Budgeted only / Unbudgeted only (formalizes FR-3.8) plus an "Over budget only" toggle. Filters apply client-side to the FR-3.6 summary cards; the overall summary (FR-3.9) always reflects the full month.

### Sub-Category Spending Breakdown

**FR-3.23:** When a budget's category is a **parent** category (has sub-categories), the budget card shows an expandable breakdown of each leaf sub-category's spend for the period: sub-category name, spent amount, and share of the budgeted amount. Example: a "Food & Dining ₹15,000" budget expands to Restaurant ₹4,200, Grocery ₹6,100, Zomato/Swiggy ₹2,900, Cafe ₹1,300.

**FR-3.24:** The breakdown is computed from transactions whose category is the sub-category itself **or** a descendant of it (i.e., transactions on the parent resolve to their own leaf category). Split transactions (Module 2 F16) count their split amounts against the split's category. No separate sub-budgets are created — the parent budget amount remains a single limit; the breakdown is informational only.

## Data Tables

### Table: budgets

The primary table storing budget configurations per category per period.

| Column | Type | Constraints | Index | Description |
|--------|------|-------------|-------|-------------|
| id | UUID | PK, DEFAULT gen_random_uuid() | PRIMARY KEY | UUID |
| user_id | INTEGER | NOT NULL, FK → users(user_id) ON DELETE CASCADE | | Multi-user owner (covered by composite `idx_bud_month_year`) |
| category_id | UUID | FK → categories(id) | | Budget category (NULL for overall budget) |
| amount | NUMERIC(12,2) | NOT NULL, CHECK(amount > 0) | | Budget amount for the period |
| period | TEXT | NOT NULL DEFAULT 'monthly', CHECK(period IN ('monthly','weekly')) | | Budget period |
| month | INTEGER | NOT NULL, CHECK(month BETWEEN 1 AND 12) | | Month (1-12) |
| year | INTEGER | NOT NULL | | Year (e.g., 2026) |
| alert_50 | INTEGER | NOT NULL DEFAULT 1 | | Alert at 50% utilization |
| alert_80 | INTEGER | NOT NULL DEFAULT 1 | | Alert at 80% utilization |
| alert_100 | INTEGER | NOT NULL DEFAULT 1 | | Alert at 100% utilization |
| rollover_enabled | INTEGER | NOT NULL DEFAULT 0 | | Enable budget rollover to next month |
| is_active | INTEGER | NOT NULL DEFAULT 1 | | Active flag |
| version | INTEGER | NOT NULL DEFAULT 1 | | Optimistic lock |
| created_by | INTEGER | FK → users(user_id) | | Audit |
| updated_by | INTEGER | FK → users(user_id) | | Audit |
| deleted_at / deleted_by | TIMESTAMPTZ / INTEGER | FK → users(user_id) | | Soft delete |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP | | Created timestamp |
| updated_at | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP | | App-managed timestamp |

**Composite Indexes:**
```sql
-- Unique constraint: one budget per user+category per month/year
CREATE UNIQUE INDEX idx_bud_category_period ON budgets(user_id, category_id, month, year);
-- Primary query: get all active budgets for a user in a given month/year
CREATE INDEX idx_bud_month_year ON budgets(user_id, month, year);
-- Query: get budgets for a specific category across months
CREATE INDEX idx_bud_category_year ON budgets(user_id, category_id, year);
```

**Performance Notes:**
- Estimated rows: 10-30 budget categories × 12 months × 20 years = **~2,400-7,200 rows** per user
- All queries filter by `user_id`, `month` and `year`, which are covered by composite indexes
- Budget dashboard query (`WHERE user_id = ? AND month = ? AND year = ? AND is_active = 1`) completes in < 0.5ms

## Database Indexing Strategy

### Index Creation SQL

```sql
-- Budgets table (multi-user aware)
CREATE UNIQUE INDEX idx_bud_category_period ON budgets(user_id, category_id, month, year);
CREATE INDEX idx_bud_month_year ON budgets(user_id, month, year);
CREATE INDEX idx_bud_category_year ON budgets(user_id, category_id, year);

-- Budget Alerts
CREATE INDEX idx_ba_budget ON budget_alerts(budget_id);
CREATE INDEX idx_ba_created ON budget_alerts(created_at);

-- Budget Rollovers
CREATE INDEX idx_br_budget ON budget_rollovers(budget_id);
CREATE INDEX idx_br_from ON budget_rollovers(user_id, budget_id, from_month, from_year);
CREATE INDEX idx_br_applied ON budget_rollovers(applied_to_budget_id);

-- Budget Templates
CREATE UNIQUE INDEX idx_bt_name ON budget_templates(user_id, name);
CREATE INDEX idx_bti_template ON budget_items(template_id);
CREATE UNIQUE INDEX idx_bti_pair ON budget_items(template_id, category_id);
```

### Query Performance Benchmarks (Target)

| Query | Target Time | Index Used |
|-------|-------------|------------|
| Get all budgets for current month (user) | < 0.5ms | idx_bud_month_year |
| Get budget for specific category + month (user) | < 1ms | idx_bud_category_period |
| Get budget history for a category (1 year, user) | < 1ms | idx_bud_category_year |
| Update budget amount | < 5ms | PRIMARY KEY |
| Calculate total budgeted for the month (user) | < 0.5ms | idx_bud_month_year (aggregate) |
| Get dashboard with all budget utilizations | < 2ms | idx_bud_month_year + transaction aggregation |
| Insert budget alert | < 5ms | idx_ba_budget |
| Apply budget template (insert 15 items) | < 15ms | idx_bti_template + idx_bti_pair |

## Suggested Enhancements

1. **Category groups in budgets** — Allow grouping related categories (e.g., "Food & Dining" could include Restaurant + Grocery + Zomato) with a single combined budget that tracks across all sub-categories. Users can toggle between individual budgets and group budgets.

2. **Annual budgets with monthly breakdown** — Users set an annual spending target per category, and the system distributes it across 12 months. Useful for non-monthly expenses like travel, gifts, or insurance.

3. **Budget vs actual trend sparklines** — Show a small inline sparkline next to each budget category showing the last 6 months of actual spending vs budgeted. This gives instant visual context on whether the budget is realistic.

4. **Seasonal budget adjustments** — Auto-adjust budgets for known seasonal patterns (higher food/entertainment in December, higher travel in summer, etc.). User could opt-in to a "seasonal mode."

5. **Budget freeze** — Allow users to "freeze" a budget for vacations or leave periods. Frozen budgets don't generate alerts and the daily spending limit is disabled. Resumes automatically when the user returns.

6. **Goal-linked budgets** — When a user creates a savings goal, the system can suggest a budget reduction in a discretionary category (e.g., "To save ₹5,000/month for your vacation, try reducing Dining Out from ₹8,000 to ₹3,000"). This bridges Module 3 (Budget) and Module 5 (Goals).
