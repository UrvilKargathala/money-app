# 10. Reports & Analytics Dashboard Module

**Module Type:** Intelligence  
**Build Phase:** Phase 2  
**Dependencies:** Module 1 (Account & Wallet), Module 2 (Transaction Engine), Module 3 (Budget), Module 4 (Bills & Subscriptions), Module 5 (Savings & Goals), Module 6 (Debt & Loan Manager), Module 7 (Tax Planning), Module 8 (Investment Tracker), Module 9 (Net Worth Tracker)

---

## Purpose

The Reports & Analytics Dashboard provides a unified visualisation layer across all MoneyMind modules. It presents key financial metrics—income vs expense, spending breakdowns, budget performance, net‑worth trends, debt payoff progress, and investment performance—in interactive charts and tables. The dashboard also serves as the entry point for AI‑generated financial summaries and on‑demand explanations of visualised data.

## Functional Requirements

### Monthly Income vs Expense Bar Chart

**FR-10.1:** Pull aggregated income and expense totals from the `transactions` table for the user‑selected month. Render a stacked bar chart using Recharts showing:
- Income (green)
- Expense (red)
- Tooltip displaying exact amounts and percentage of total.

### Spending Breakdown Charts

**FR-10.2:** Group expense transactions by `category` for the selected period and produce:
- A donut chart with segment size representing total spend per category.
- A horizontal bar chart listing categories sorted by spend descending.
- Ability to click a segment to drill down to a transaction list filtered by that category.

### Spending Trend Line Chart

**FR-10.3:** Compute cumulative spend per month for the past 3, 6, and 12 months (user selectable). Plot each category as a separate line (or an aggregated total line) on a Recharts line chart. Include zoom/pan controls.

### Budget vs Actual Comparison

**FR-10.4:** The Budget vs Actual chart **consumes Module 3's computed metric** (FR-3.13 — actual spend per category from transactions/splits, budgeted from `budgets`; Module 3 owns the calculation, this module only visualizes it). For the current month, render a side‑by‑side bar chart with colour coding (budget in blue, actual in orange) and highlight overruns in red.

### Daily Spending Heatmap Calendar

**FR-10.5:** Generate a calendar grid for the selected month where each day cell’s background colour intensity corresponds to total spend that day. Provide tooltip with exact amount and optionally link to the day’s transaction list.

### Net Worth Over Time Line Chart

**FR-10.6:** Consume data from the `net_worth_snapshots` table (module 9) and render an interactive line chart. Hover tooltip shows date, net‑worth, assets total, liabilities total, and % change from previous day.

### Debt Payoff Progress Chart

**FR-10.7:** For each active debt (from the `debts` table), calculate:
- Original principal
- Outstanding principal
- Amount paid to date
Render a stacked bar or funnel chart visualising remaining vs paid principal; include projected payoff date based on current EMI.

### Custom Date‑Range Filtering

**FR-10.8:** Provide a UI component (date picker) allowing the user to set any start and end dates. All charts and tables should reactively re‑query their underlying data using the selected range.

### Export Reports as PDF

**FR-10.9:** When the user clicks “Export PDF”, generate a PDF containing:
- Title page with selected date range and report generation timestamp.
- All active charts rendered as high‑resolution images.
- Tables summarising key metrics (e.g., total income, total expense, net‑worth summary).
- Footer with page numbers and optional user‑defined notes.
Implementation uses `jsPDF` or `@react-pdf/renderer` as defined in the tech stack.

### Explain‑This Feature

**FR-10.10:** When a user selects a chart and presses “Explain”, the system assembles a minimal data snapshot relevant to that chart and sends it to the Claude API with a system prompt: *“Generate a concise plain‑English explanation of the displayed data, highlight any notable trends, and suggest a possible action.”* The response is displayed in a modal beneath the chart.

**FR-10.10a (data-safety guardrails):** The Explain-This payload contains **only aggregated numerical data** (totals, percentages, date ranges) **and category names** — never account identifiers, transaction descriptions, merchant names, account/card numbers, or any data from Module 11 (Secure Notes). A user **consent toggle in Settings (default: off)** gates the feature. AI responses are **ephemeral** — displayed once and never cached or logged server-side.

### Income Sources Breakdown

**FR-10.11:** Group income transactions (type = income) by their category for the selected period and render a donut chart + horizontal bar list (source category, amount, share %). Sources with zero income in the period are omitted; a "Total Income" summary head is shown. Clicking a slice drills down to the filtered transaction list (same pattern as FR-10.2).

### Top Merchants

**FR-10.12:** Aggregate expense transactions by `merchant_clean` (falling back to `description` when clean is null) for the selected period and render a ranked list: merchant, total spend, transaction count, and average amount, sorted by spend descending (top 10, expandable to top 25). A "frequency" toggle re-sorts by transaction count. Merchants with ≥ 3 transactions in the period are highlighted as recurring spend patterns.

### Tab-Based Navigation

**FR-10.13:** The dashboard is organized into tabs: **Cash Flow** (FR-10.1), **Categories** (FR-10.2), **Trends** (FR-10.3), **Heatmap** (FR-10.5), and **Summary** (combined key metrics: total income, total expense, net, top category, top merchant, budget overruns, net worth, debt totals). The date-range filter (FR-10.8) and Export PDF (FR-10.9) live in the shared action bar above the tabs and apply to the active tab.

## Data Tables

### Table: report_templates

Defines the available pre‑built report templates that can be rendered in the dashboard.

| Column | Type | Constraints | Index | Description |
|--------|------|-------------|-------|-------------|
| id | UUID | PK, DEFAULT gen_random_uuid() | PRIMARY KEY | UUID |
| user_id | INTEGER | FK → users(user_id); **NULL for system templates** | INDEX idx_rt_user | Owner; NULL = global system template |
| name | TEXT | NOT NULL | INDEX idx_rt_name | Human‑readable template name (e.g., "Monthly Summary") |
| description | TEXT | | | Short description of what the report contains |
| chart_config | JSONB | NOT NULL | | JSON describing which charts/tables are part of this template |
| version | INTEGER | NOT NULL DEFAULT 1 | | Optimistic lock |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP | | Created timestamp |
| updated_at | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP | | App-managed timestamp |

**Unique constraints (multi-user + system rows):**
```sql
-- User templates: unique per owner
CREATE UNIQUE INDEX ux_report_templates_user_name ON report_templates(user_id, name) WHERE user_id IS NOT NULL;
-- Seeded system templates: unique among system rows only
CREATE UNIQUE INDEX ux_report_templates_system_name ON report_templates(name) WHERE user_id IS NULL;
```

**Performance Notes:**
- Very small table. Index on `user_id, name` enables quick lookup when a user selects a template.
- **System templates** (`user_id IS NULL`) are seeded via migration scripts and are **immutable at runtime** — no UI to create/edit/delete them. Only user templates (`user_id IS NOT NULL`) can be created/edited/deleted via the UI.

### Table: report_exports

Tracks each PDF/CSV export request generated from the dashboard.

| Column | Type | Constraints | Index | Description |
|--------|------|-------------|-------|-------------|
| id | UUID | PK, DEFAULT gen_random_uuid() | PRIMARY KEY | UUID |
| user_id | INTEGER | NOT NULL, FK → users(user_id) ON DELETE CASCADE | INDEX idx_re_user | Multi-user owner |
| template_id | UUID | NOT NULL, FK → report_templates(id) | INDEX idx_re_template | The template that was exported |
| file_path | TEXT | NOT NULL | | Absolute path to the generated file |
| file_type | TEXT | NOT NULL, CHECK(file_type IN ('pdf','csv')) | | Export format |
| date_range_start | DATE | NOT NULL | | Start date of the data range covered |
| date_range_end | DATE | NOT NULL | | End date of the data range covered |
| created_at | TIMESTAMPTZ | NOT NULL DEFAULT CURRENT_TIMESTAMP | | Export request timestamp |

**Performance Notes:**
- Index on `template_id` speeds queries for “show my recent exports of this template”.
- Typically < 100 rows per user, so queries are sub‑millisecond.

## Suggested Enhancements

1. **Custom Dashboard Builder** – Let users compose their own dashboard pages by dragging and dropping individual chart widgets, persisting the layout in a new `user_dashboards` table.
2. **Scheduled Report Generation** – Add a cron‑based feature that automatically generates a selected report (e.g., monthly financial summary) and saves it to a user‑defined folder or emails it.
3. **Multi‑Language Support** – Store locale information per report export so PDFs can be generated in English, Hindi, or other regional languages.
4. **Interactive Drill‑Through** – Extend the “Explain‑This” feature to include a clickable link that opens a filtered transaction list view directly from the explanation modal.
5. **Export to Power BI/Excel** – Provide an option to export raw data underlying each chart as an Excel workbook with separate sheets for each metric, enabling power users to perform deeper analysis.
6. **Dark‑Mode Optimised Charts** – Detect the app theme (light/dark) and render chart colours accordingly for better readability.
7. **AI‑Generated Insight Summaries** – Schedule a background AI job that produces a concise narrative summary of the month’s financial health and attaches it to the exported PDF as a “Insights” section.
8. **Versioned Report Templates** – Add a `version` column to `report_templates` so changes to a template’s chart configuration can be tracked and rolled back if needed.
9. **User Permission Controls** – In multi‑user scenarios (future feature), store access rights per report template to restrict who can view or export sensitive financial reports.
