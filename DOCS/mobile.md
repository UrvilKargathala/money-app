## 1. Architecture

MoneyMind is a **server-rendered Next.js app with an embedded Hono API** (`/api/*`). A mobile app therefore cannot bundle static files — the WebView must load a running server. Capacitor provides the native shell (system WebView + native plugins):

```
┌─ Android app / iOS app ────────────────────────────────┐
│  Capacitor shell (system WebView)                       │
│  └─ loads <server.url> — the Next.js app                │
│       ├─ all UI + server actions work as on the web     │
│       ├─ mm_session cookie persists in WebView storage  │
│       └─ deep-link listener → /add (wired, Phase 1)     │
│  (Phase 2) widget / icon shortcut / App Intent          │
│      └─ deep link moneymind://add ──▶ /add page ──▶     │
│         POST /api/transactions ──▶ PostgreSQL           │
└─────────────────────────────────────────────────────────┘
```

- **One codebase, one deployable.** The web app *is* the mobile app; the native projects are thin shells.
- **Sessions:** the WebView keeps the `mm_session` cookie like a browser; login/logout work unchanged. Cookie persistence across app restarts is provided by the platform WebView (WKWebView / Android WebView persistent storage).
- **Deep links:** `@capacitor/app` listener in `src/components/mobile/deep-link-handler.tsx` routes `moneymind://add` (and http(s) URLs whose pathname is `/add`) to the quick-add page. Unauthenticated visits are redirected to `/login` by the existing proxy middleware.

### Why not bundle the web app (PWA-style)?
Next.js server components, server actions and the embedded API need a server. Bundling would require rewriting every page as a client component and a second API origin — exactly what the UI↔API split (§ 5.2 in hosting doc) exists to avoid. The WebView loads the deployed app; offline is out of scope (fine for a personal finance app).

## 2. Repository Layout

```
android/                  # Native Android project (generated by `cap add android`, committed)
mobile-web/index.html     # Placeholder webDir — WebView falls back to it only if server.url is unreachable
capacitor.config.ts       # appId, appName, webDir, server.url
src/components/mobile/deep-link-handler.tsx   # Deep-link → /add routing (native only)
src/app/(app)/add/        # Quick-add page + proxy action (POST /api/transactions)
src/components/layout/bottom-nav.tsx          # Mobile bottom navigation (Home / Add FAB / Accounts)
```

`webDir` points at `mobile-web/` (a placeholder), not `.next/` — the Next build directory contains pnpm symlinks that break `cap sync` on Windows, and the app never loads local assets anyway (server.url always).

## 3. Prerequisites (Windows → Android)

| Tool | Why |
|---|---|
| Node 20 LTS+ / pnpm | Web app + `@capacitor/cli` |
| **JDK 21** (not 17, not 25) | Capacitor 8 / AGP 8.7 compiles with source level 21. `JAVA_HOME` must point at a JDK 21 |

## 4. Server URL — Dev vs Production

`capacitor.config.ts` `server.url` decides what the app loads:

| Build | `server.url` | Notes |
|---|---|---|
| Dev, Android emulator | `http://10.0.2.2:3000` | Emulator loopback → host's `pnpm dev` |
| Dev, physical phone — **USB** | `http://localhost:3000` | Combined with `adb reverse tcp:3000 tcp:3000` — no Wi‑Fi/firewall needed (recommended; full steps in `DEV-ENV.md` § 10) |
| Dev, physical phone — Wi‑Fi | `http://<your-LAN-IP>:3000` | Device and PC on the same Wi‑Fi; Next dev binds all interfaces by default |
| Production | `https://<deployed-url>` | The Vercel deployment (see hosting doc § 5.4) |

- HTTP (`http://`) is allowed only because `android:usesCleartextTraffic="true"` is set in `android/app/src/main/AndroidManifest.xml` — **remove that attribute for store release** (the production URL is https and never needs it).
- Keep `androidScheme: "https"` — it is the scheme of the internal WebView bridge, unrelated to `server.url`.

## 5. Build & Run Workflow (Android, Windows)

```bash
# 1. Start the web app (separate terminal)
pnpm dev

# 2. Sync the native project with the current config/plugins
npx cap sync android

# 3. Build the debug APK (JDK 21 required)
cd android
.\gradlew.bat assembleDebug        # or: cd .. && npx cap open android → Android Studio

# 4. Install on emulator/device (adb already configured on this machine)
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

Release build: `.\gradlew.bat assembleRelease` — requires signing config (see § 7).

### Typical iteration loop
1. Edit web code → `pnpm dev` hot-reloads → the app's WebView refreshes on reopen (or pull-to-refresh via dev menu).
2. Native-only changes (manifest, plugins) → `npx cap sync android` → rebuild APK → reinstall.

## 7. Store Release Checklist

1. `server.url` → deployed https URL; remove `usesCleartextTraffic` from the manifest.
2. App icons / splash: replace Capacitor defaults in `android/app/src/main/res/` (and `ios/App/App/Assets.xcassets`).
3. Signing: create a keystore (`keytool`), configure `android/app/build.gradle` `signingConfigs`, set `android:versionName`/`versionCode` to match the web release.
4. Android: upload the signed AAB (`gradlew bundleRelease` → `app-release.aab`) to Google Play.
5. iOS: archive in Xcode → App Store Connect.
6. Versioning note: the app is a thin shell — bump the app version when the *web deploy* changes too, so stores show a fresh "What's New".

## 8. Phase 2 — Shortcut Flows (Roadmap, NOT built yet)

All entries funnel into the existing deep link `moneymind://add` → `/add` → `POST /api/transactions`.

| Feature | iOS | Android |
|---|---|---|
| Home-screen widget (tap → quick-add) | WidgetKit button (Swift) — needs Mac | AppWidgetProvider (Kotlin) → `PendingIntent` with `moneymind://add` data URI |
| App icon long-press | Quick Actions (`UIApplicationShortcutItem`) | Dynamic App Shortcuts |
| **Back Tap** (double/triple tap on phone back) | **App Intents** (iOS 16+): a small Swift `AddTransactionIntent`; the *user* assigns it in Settings → Accessibility → Touch → Back Tap. Same intent powers Action Button (15 Pro+), Control Center (iOS 18), Lock Screen widget, Siri | ❌ Android has no universal back-tap (OEM-only gestures, not app-controllable) — the home-screen widget is the equivalent |
| Voice | Siri Shortcuts (via App Intents) | Assistant App Actions (later) |
| Push notifications | APNs via plugin | FCM via plugin |

Notes:
- Back Tap is **user-assigned by design** (Apple privacy) — apps cannot bind gestures programmatically; the app only ships the intent + setup docs.
- Widgets cannot contain text input on Android (`RemoteViews`); the standard pattern is widget tap → full-screen quick-add keypad.
- Existing `deep-link-handler.tsx` already routes `/add` — Phase 2 only adds native entry points that fire the same URL.

## 9. Troubleshooting

| Symptom | Cause → Fix |
|---|---|
| `invalid source release: 21` | `JAVA_HOME` is an old JDK (17 on this machine) → install/point at **JDK 21** (e.g. Temurin 21) and set `JAVA_HOME` before building; or add `org.gradle.java.home=<path-to-jdk21>` to `android/gradle.properties` |
| Gradle won't start on Java 25 | Gradle 8.14 supports running on ≤ Java 24 → use JDK 21, not the Zulu 25 on PATH |
| `cap sync` fails copying `.next` | Expected — keep `webDir: "mobile-web"` (Next build output contains pnpm symlinks; EPERM on Windows) |
| Blank screen / "net::ERR_CLEARTEXT_NOT_PERMITTED" | `usesCleartextTraffic` missing while `server.url` is http |
| App loads but API calls fail (dev) | `server.url` reachable but wrong origin for cookies → the WebView origin **is** the API origin (same `server.url`), so cookie mismatch only happens if `server.url` differs from the host the page was first loaded from — keep it stable |
| Physical phone can't reach dev server | Prefer USB: `adb reverse tcp:3000 tcp:3000` with `server.url: http://localhost:3000`. Over Wi‑Fi: use the PC's LAN IP (same network), allow port 3000 inbound in Windows Firewall |
| Cookie lost after app update/reinstall | Platform WebView storage reset — user logs in again (expected) |
